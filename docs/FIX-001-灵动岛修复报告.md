## 1. 缺陷回顾

| 编号 | 现象 | 根因（一句话） |
| --- | --- | --- |
| BUG-001 | 灵动岛收起态第二行文字被裁切、下边缘贴死、行距不均 | 容器高度**写死 `height: 46`**，而 Android 中文字体默认 `includeFontPadding: true`，两行内容实际需约 65pt，超出部分被 `overflow: hidden` 裁掉 |
| BUG-002 | 展开/收起高度插值退化为常量，展开动画失去高度变化 | 收起态与展开态**共用一个高度 state** 且初值相同，而展开态组件始终渲染（仅 `opacity: 0`），未展开时其 `onLayout` 也在写值，两个测量源互相覆盖 |

完整取证见 `docs/BUG-001-灵动岛文字裁切.md`。

## 2. 修复方案与实现

### 2.1 BUG-001：高度不再硬编码，改由内容实测驱动

| # | 改动 | 修复的根因 |
| --- | --- | --- |
| 1 | `collapsedH` / `expandedPanelH` 初值由 `46` 改为 `0`，两态高度全部由 `onLayout` 实测写入 | 写死高度容纳不下两行 |
| 2 | 两个高度**都未测出前不设 `height`**，让内容自然撑开；测出后才交给 `Animated.interpolate` | 首帧必然先裁一次、随后跳变 |
| 3 | 全部文本加显式 `lineHeight`（13→18、11→16、15→21）、`includeFontPadding: false`、`maxFontSizeMultiplier={1.3}` | 中文字体每行额外占 4-6pt；大字号撑爆 |

核心代码：

```tsx
const ready = collapsedH > 0;
const openH = expandedPanelH > 0 ? collapsedH + expandedPanelH : collapsedH;
const height = ready
  ? anim.interpolate({ inputRange: [0, 1], outputRange: [collapsedH, Math.max(openH, collapsedH)] })
  : undefined;   // 未测出 → 不约束高度，内容自然撑开
```

附带改动：收起态层由「随内容参与布局 + `alignItems: 'center'`」改为**绝对定位锚在左上角**
（`styles.collapsedLayer`）。原因：外层高度一旦由动画接管，`alignItems: 'center'` 会依赖父容器高度，
在父高未定时造成裁切或偏移。

### 2.2 BUG-002：展开态独立测量

展开面板改为**仅在展开时渲染**，并单独测量其自身高度：

```tsx
{expanded ? (
  <Animated.View style={[styles.expanded, { opacity: anim }]}>
    <View onLayout={(e) => setExpandedPanelH(Math.ceil(e.nativeEvent.layout.height))}>
      …展开内容…
    </View>
  </Animated.View>
) : null}
```

这样 `expandedPanelH` 量到的是展开面板自身高度（不再被收起态干扰），
动画终值取 `collapsedH + expandedPanelH`，两个状态不再互相覆盖。

## 4. 验证过程本身的坑（已修正，供复用）

第一版验证脚本给出了**假阴性**，根因都在脚本而非产品代码：

| 现象 | 根因 | 修正 |
| --- | --- | --- |
| 点击灵动岛无效，展开态测不出 | 合成 `element.dispatchEvent(new MouseEvent('click'))` **驱动不了 RN Web 的 Pressable**（它走 Responder 系统，只认真实 pointer/touch 输入） | 改用 CDP `Input.dispatchMouseEvent` 派发真实鼠标事件 |
| 脚本"静默失效"，返回 undefined | CDP `Runtime.evaluate` 传字符串会被当作**函数声明**编译而非表达式求值 | 一律包成 IIFE `(() => { …; return v; })()` |
| 想测「无课」却仍显示课程 | App 启动后把自身 state 写回存储，**覆盖了脚本刚写的种子数据** | 改用 `Page.addScriptToEvaluateOnNewDocument` 注入（每次导航前执行） |
| 首次测得 42，误以为高度不对 | 首帧是内容自然高度，`onLayout` 写回后才是终值 | 增加 `waitStableHeight()` 等高度稳定 |

这些教训已写入 `memory/experience.md`（第 8–12 条）。

以下两项**本次未能验证**，因为验证环境是 Web 渲染，没有真实 Android 字体度量与系统字号设置：

- [ ] 系统字体调至最大（`fontScale` 1.3）时不裁切

> **重要说明**：Web 无 `includeFontPadding`，故 Web 上收起态内容高仅 18pt，而 Android 上同一内容会更高。
> 本次验证证明的是**「高度由实测驱动」这一修复机制成立**——容器会随 Android 更高的内容自动变高，
> 这正是选用实测而非写死数值的原因。但 Android 上的**最终像素值**仍需真机复核。
