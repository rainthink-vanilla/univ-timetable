# 大学课表（md 版）· 项目技术文档

版本：v1.1.0　|　契约版本：`univ-timetable/v1`　|　平台：Android（APK）/ Web / iOS

---

## 1. 项目定位

一句话：**把「教务系统里我的课表」变成一份手机 App 能直接吃下去的文件。**

传统做法是每个学校写一套爬虫，维护成本高、教务系统一改版就废。本项目换一条路：

```
用户在 .md 里填账号密码 + 爬取范围
        ↓
通用 agent（能读文件、能操作浏览器）按引导登录教务系统
        ↓
产出「统一契约格式」的 .md 文件（人可读表格 + 机器可读 JSON）
        ↓
手机 App「文件导入」→ 解析 → 本地课表（当周视图 / 当日视图）
        ↓
提醒用户改密码
```

**核心思想**：把「爬取」这件最脏最不稳定的活交给 agent，App 只负责**消费一份稳定的数据契约**。教务系统怎么变，App 都不用改。

## 4. 数据契约（本项目的心脏）

### 4.1 文件结构

一份课表文件 = **四段**：

| 段 | 内容 | 谁读 |
| --- | --- | --- |
| 一、课表元信息 | 学校 / 学期 / 开学日期 / 覆盖周次 / 爬取范围 | 人 + App |
| 二、节次时间表 | 第 N 节 = 起止时间（**各校作息不同**） | 人 + App |
| 三、课程明细 | Markdown 表格，一门课一行 | 人（核对） |
| 四、机器可读数据 | ```` ```json ```` 代码块，`univ-timetable/v1` | App（优先） |

### 4.2 JSON Schema（简化）

```jsonc
{
  "contract": "univ-timetable/v1",
  "meta": {
    "school": "示例大学",              // 可选
    "jwcURL": "https://...",           // 可选，导入后写入设置
    "semester": "2025-2026 学年第一学期",
    "semesterStart": "2025-09-01",     // 用于计算「第几周」
    "totalWeeks": 20,                  // 用于周次上限
    "weekRange": "1-16",               // 本次抓取覆盖的周次
    "scope": "all",                    // all|term|week|day|month|custom
    "student": "张三",
    "studentId": "20250001",
    "scrapedAt": "2025-09-10T08:00:00.000Z"
  },
  // 可选：节次时间表（有则导入时同步到 App 设置）
  "periods": [
    { "index": 1, "start": "08:30", "end": "09:15" },
    { "index": 2, "start": "09:25", "end": "10:10" }
  ],
  "courses": [
    {
      "name": "高等数学A",              // 必填
      "teacher": "张三",
      "location": "教一101",
      "dayOfWeek": 1,                   // 必填，1=周一 … 7=周日
      "startPeriod": 1,                 // 必填，从 1 开始
      "endPeriod": 2,                   // 必填，连堂填末节
      "weeks": [1,2,3],                 // 必填，升序去重数字数组
      "note": ""                        // 可选
    }
  ]
}
```

### 4.2.1 节次时间表的三种写法

各校作息差异很大（有的 8:00 上课、有的 8:30），因此契约支持三种写法，按需选一种：

| 写法 | 示例 | 适用 |
| --- | --- | --- |
| `periods` 数组（**最规范**） | `[{"index":1,"start":"08:30","end":"09:15"}, …]` | 教务系统能直接取到每节时间 |
| `periodTimes` 数组（别名容忍） | `[{"period":1,"time":"08:30-09:15"}, …]` | 抓到的字段名不统一时 |
| `periodTimes` 对象（**最省事**） | `{"start":"08:30","duration":45,"break":10,"count":12}` | 只知道第 1 节时间，其余按 45/10 推算 |

字段名做了别名容忍：`index/period/no/seq/节次`、`start/begin/from/开始/开始时间`、
`end/finish/to/结束/结束时间`、`time/range/时间`（支持 `"08:30-09:15"` 组合写法）。
时间格式接受 `08:30` / `8:30` / `8：30`（全角）/ `0830` / `830` / `8点` / `8点10分`。

解析实现见 `parsePeriodTimes()`；`periods` 缺失时还会从正文的「节次时间表」Markdown 表格兜底。

> **导入行为**：只有文件**明确给出**节次时间时才覆盖 App 设置；文件没给则保留用户现有设置。
> 这样日常更新（01/02 文档默认不带节次时间）不会把用户手动调好的作息冲掉。

### 4.3 解析策略（`src/utils/timetableFile.ts`）

三层降级，容错优先：

```
① ```json 代码块  →  标准契约，取 meta + courses
② Markdown 表格   →  表头按别名匹配（课程/教师/地点/星期/节次/周次），列顺序随意
③ 宽松兜底        →  非标准字段名（course/day/time/weekday）尽力识别，并给出警告
```

解析细节：

- **星期**：`周一 / 星期一 / 周1 / 1 / Mon / Monday` 都能识别 → `1-7`。
- **节次**：`第1-2节 / 1-2 / 3 / 第 11-12 节` → `{start, end}`，自动纠正倒序。
- **周次**：`1-16 / 1-16周(单) / 1-8,10-12 / 数组` → 升序数字数组。
- **元信息兜底**：JSON 里没有 meta 时，从正文「项目|内容」表格或 `键：值` 行里抓。

### 4.4 契约稳定性

- 新增字段必须**可选**，旧 App 必须能忽略它继续工作。
- `contract` 字段用于未来版本演进；当前解析器不因版本号不同而拒绝文件。
- 表格与 JSON 冲突时**以 JSON 为准**（表格给人看）。

### 4.5 「星期」列可以写多天（v1.7.1 明确）

契约上 `dayOfWeek` 是**单值**（1=周一 … 7=周日），但**表格/JSON 里允许一格写多天**，
App 会把它**展开成多条课程**（每天一条，其余字段相同）：

| 写法 | 展开结果 |
| --- | --- |
| `周六、周日` / `周六/周日` / `周六和周日` / `周六 周日` | 6、7 各一条 |
| `六日` / `周六周日`（连写） | 6、7 各一条 |
| `6,7` / `6-7` / `周六-周日`（区间） | 6、7 各一条 |
| `周末` / `双休` | 6、7 各一条 |
| `工作日` / `一至五` / `周一到周五` | 1~5 各一条 |
| `每天` / `全周` | 1~7 各一条 |
| `0` | 视为 **7（周日）** |
| JSON 数组 `[6,7]` | 6、7 各一条 |

> 实现：`normalizeDays()`（纯函数）；`normalizeDay()` 保留为单值版本（取第一个），供旧调用点使用。
> 注意：**展开后的多条课程互不关联**——改其中一条不会同步改其他天（刻意如此，便于单独调某一天）。

## 7. 关键实现细节

### 7.1 为什么用运行时 `require` 而不是顶层 `import`

`expo-file-system` 是 `expo` 包的依赖，可能被提升到顶层，也可能嵌套在 `expo/node_modules` 下。更重要的是：**用户手机上装的可能还是旧 APK**（不含新代码路径）。如果用顶层 `import`，模块缺失会导致整个界面白屏。

因此 `fileImporter.ts` 用 `require('expo-file-system')` 并在 `try/catch` 里做能力检测：

```ts
const picker = fs && fs.File && fs.File.pickFileAsync;
if (typeof picker !== 'function') {
  return { ok: false, kind: 'no-picker', message: '当前安装的 App 版本还不支持「选择文件」导入（需要重新构建 APK）…' };
}
```

**旧 APK 上表现为一条友好提示，而不是崩溃。**

### 7.2 导入后的设置同步

文件里的 `semesterStart`、`totalWeeks`、`jwcURL`、`meta` 会写回 App 设置，因此用户**不需要手动填开学日期**——这是「第几周」计算正确的前提。

### 7.3 数据落地

- 课表与设置存在 `AsyncStorage`，key 为 `univtimetable/courses/v1`、`univtimetable/settings/v1`。
- 离线可看，不联网也能用。
- 设置页支持「导出 JSON」备份、换机迁移。

### 7.4 可配置颜色不能写进 `StyleSheet`（v1.6.0 修复的 BUG）

`StyleSheet.create()` 在**模块加载那一刻**就把颜色字面量固化了。因此

```ts
// ❌ 改设置后界面毫无变化
const styles = StyleSheet.create({ fab: { backgroundColor: palette.accent } });
```

`settings.accentColor` 虽然存进了设置，却没有任何界面元素读它 —— 这正是 v1.5.0
「主题色无法正常更改」的根因（当时只有色块上的对勾会移动）。

正确做法：**渲染期取色**。强调色由 `AccentProvider` 统一下发，组件用内联样式覆盖：

```tsx
const { accent, accentSoft, accentTint } = useAccent();
<Pressable style={[styles.fab, { backgroundColor: accent, shadowColor: accent }]} />
```

- `src/theme.ts`：`normalizeHex()` / `withAlpha()` / `accentTokens()`（纯函数，可单测）；
- `src/store/AccentContext.tsx`：`AccentProvider` + `useAccent()`，**无 Provider 时回退默认色**（组件不抛错）；
- 课程卡片颜色**不属于**强调色体系（它是课表内容，由每门课自己的 `color` 决定）。

### 7.5 Web 上 `Paths.document` 是会抛异常的 getter（v1.6.0 修复）

```ts
// ❌ 异常发生在 try 之外：整段持久化被跳过，用户点「确认」后什么都没保存
const fs = loadFs();
if (!fs || !fs.Paths?.document || !fs.File) return fallback;   // ← 这里访问就抛
try { /* 复制图片 */ } catch { /* 兜底 */ }
```

Web 上 `require('expo-file-system')` 返回的是"不支持"存根，**读取 `Paths.document` 本身抛
`TypeError: this.validatePath is not a function`**。修法两条：

1. 所有文件系统访问移入 `try`（`utils/themeImage.ts`）；
2. 调用方**先兜住异常也一定写设置**（`CustomTheme.persist()`），绝不出现"确认后静默丢弃"。

### 12.1 v1.2.1 修复记录

详见 `docs/FIX-001-灵动岛修复报告.md`。要点：

**BUG-001（灵动岛文字被裁切）** —— 容器高度写死 `height: 46`，而 Android 中文默认
`includeFontPadding: true`，两行内容合计约 65pt，超出部分被 `overflow: hidden` 裁掉。三处联合修复：

1. 高度不再硬编码：收起态与展开面板各自 `onLayout` 实测，用 `Animated.interpolate` 插值；
2. 两个高度都未测出前**不设** `height`，让内容自然撑开（避免首帧先裁一次再跳变）；
3. 文本加显式 `lineHeight` + `includeFontPadding: false` + `maxFontSizeMultiplier={1.3}`。

另将收起态层由「参与布局 + `alignItems: 'center'`」改为**绝对定位锚在左上角**：
外层高度由动画接管后，居中会依赖父容器高度，父高未定时造成裁切/偏移。

**BUG-002（展开动画失效）** —— 两态共用一个高度 state 且初值相同，而展开态组件始终渲染
（仅 `opacity: 0`），未展开时其 `onLayout` 也在写值。改为**展开面板仅在展开时渲染**并单独测量，
终值取 `收起高 + 展开面板高`。

**验证**：新增 `npm run verify:island`（Web 构建 + 无头 Chrome + CDP 真实鼠标事件），
三场景 6/6 通过——收起 42pt / 展开 112pt / 无课 42pt，均不裁切、下留白 12pt。

> **Web 与 Android 的差异**：Web 无 `includeFontPadding`，量到的数值小于 Android。
> 该验证证明的是「高度由实测驱动」机制成立，Android 最终像素值仍需真机复核。

**关键设计：非破坏性裁剪** —— 只存「裁剪矩形 + 原图尺寸」（`CropEntry`），不改动图片文件。

| 为什么这样做 | 说明 |
| --- | --- |
| 零新增原生模块 | 加 `expo-image-manipulator` 会引入新的原生依赖与构建风险（本机无 Android SDK，只能 EAS 云构建），且 Web 端行为不一致 |
| 不损失画质 | JPG 每次重编码都会掉画质，反复裁剪会累积损失；存矩形则原图不动 |
| 跨屏幕稳健 | 按容器比例重新 cover，不会出现「裁好的图在别的屏幕上被二次裁掉」 |
| 可反向调整 | 原图保留 → 随时「重新裁剪」，甚至能把范围拉大 |
| 可自动化验证 | 不需要读回图片像素，Web 与 Android 行为一致，能被无头浏览器断言 |

几何计算（全部纯函数，16 项单测锁定）：

| 函数 | 职责 |
| --- | --- |
| `layoutForCrop(rect, src, boxW, boxH)` | 裁剪区域以 cover 铺满容器时，图片的绝对定位与尺寸（`CroppedImage` 用它渲染） |
| `transformForCrop(rect, src, fw, fh)` | 让给定裁剪区域正好铺满预览框（打开裁剪器时的初始视图） |
| `clampTransform(t, src, fw, fh, maxScale?)` | 钳制到「图片始终盖住裁剪框」 |
| `rectFromTransform(t, src, fw, fh)` | 由当前变换反算可见区域 = 用户最终得到的裁剪结果 |
| `croppedSize(rect, src)` / `cropMeetsMinSide()` | 「裁剪后 1080×1920」提示与最短边告警 |
| `fitBox(areaW, areaH, aspect)` | 预览框按比例取最大居中矩形 |

> ⚠️ **踩坑（实测）**：`clampTransform` 最初把「当前裁剪框」当作约束对象，
> 于是缩小后裁剪框正好铺满预览框、可拖动余量恒为 0，表现为**「放大后怎么拖都不动」**。
> 改为约束**整张原图**后平移正常（并额外获得「可反向拉大范围」的能力）。
> 另外 `maxScale` 需要放宽到「初始缩放」，否则重新裁剪一个很小的旧区域时，一打开就被压回去。

交互：`PanResponder` 单指拖动 + 双指捏合缩放 + ＋/－ 按钮（键盘/鼠标场景）+ 重置；
比例胶囊（背景 全屏/9:16/1:1，图标固定 1:1）；实时尺寸与过小告警。

### 12.7 v1.7.0 新增：地点换行 / 图片尺寸放宽 + 双指缩放 / 分列修复 / 三标签图标

#### ① 重叠课程分列排布（`src/utils/layout.ts` + `WeekGrid.tsx`）

**BUG 现象**：同一天两门课时间重叠（含节次完全相同）时，两块都以 `left/right=1` 铺满整列，
后画的把先画的**整块盖住** —— 用户看到"课程图标重合、一门课消失"。

**算法**（纯函数，8 项单测锁定）：

1. 按开始节次排序（同开始则节数多的在前，大块先占位）；
2. 扫一遍把课程切成**重叠连通簇**（`c.start > 簇内最大 end` 即开新簇）；
3. 簇内**贪心分列**：放进第一条"最后结束节次 < 本课开始节次"的空列；
4. 同簇所有块用**同一个列数** `lanes` 等宽排布，`laneBox()` 换算像素并留 `LANE_GAP=2`；
5. 不重叠的课自成单列簇 → `lanes=1` → **仍占满整列**，不会被无谓压窄。

竖直方向：`top = (start-1)*ROW_HEIGHT + 2`、`height = span*ROW_HEIGHT - 4`，
相邻块之间固定留 4px；块加 1px 半透明描边便于分辨。

> 取舍：贪心分列未必是理论最优（可能多用一列），但**稳定、可预期、O(n log n)**，
> 对课表这种小规模输入足够；且"永不重叠"这一硬保证由算法结构直接给出。

#### ② 地点自动换行（`WeekGrid.tsx`）

- 地点**不再限 1 行**：按块高换算可显示行数

- **并排变窄的块自动换小字号**（课程名 9→8px、地点 8→7px、行高 11/10→10/9），

### 12.8 v1.7.1：周六/周日串列修复 + 设置页分类抽屉

#### ① BUG 根因在**解析层**，不在布局（`utils/timetableFile.ts`）

**用户报告**：周六与周日同一时段的课都挤进周六那一列。

**排查过程**（值得记录的方法）：先在浏览器里用「七天各一门同节次课程」的种子数据量 7 列几何 ——
393 / 360 / 320 三种宽度下七列都各就各位、不重叠 → **布局没问题**。
于是转到数据侧，直接对解析函数做表驱动测试，立刻暴露：

```
normalizeDay('周六、周日') → 6      // 只取第一个匹配到的星期
```

`normalizeDay` 是按「一/二/…/六/日」顺序做 `indexOf` 的，遇到"一格多天"只会返回**最先命中**的那个，
于是"周六、周日"这类写法被压成周六 —— 表现正是"周日的课被塞进周六列、周日整列空着"。

**修复**：新增 `normalizeDays()`（多天 → 升序去重数组），并让**表格与 JSON 两条路径都按天展开成多条课程**。
识别规则见第 4.5 节（语义词 / 区间 / 分隔符 / 连写 / 数组 / 0=周日）。

**关键取舍**：展开成"多条"而不是给 `Course` 加 `days: number[]` ——
① 数据模型、合并导入（`sameCourse` 用「课程名+星期+开始节次」）、分列排布、详情页都不用动；
② 用户可能只想改其中一天（如"周日那节换教室"），展开后天然支持。

#### ② 顺带修掉的几何隐患（`WeekGridBody`）

同一轮排查还发现：`WeekGridBody` 用 `useWindowDimensions()` 的**窗口宽度**算列宽，
但它在「周次预览」弹层里是**带 16px 左右内边距**渲染的 —— 七列总宽超出容器，
最右侧（周六/周日）被挤出可视区（实测周日列右边界 411 > 窗口 393）。

修法：
1. 根节点 `onLayout` **实测自身宽度**，列宽按 `实测宽 - 时间轴 - 内边距` 计算（未实测前用窗口宽兜底）；
2. 时间轴与各列显式 `flexGrow: 0 / flexShrink: 0` —— **禁止 flex 再压缩**（这是"两天的课被挤到一起"的隐患来源）；

### 12.9 v1.7.2：列排版结构性重做 + 脏数据兼容 + 课表自检

#### ① 为什么在 v1.7.1 之后还要再修一次（问题定位过程）

v1.7.1 修的是**解析层**（`周六、周日` 只取第一个星期 → 各生成一条），但用户反馈仍未解决。
这一次不再赌单点，而是先把**可能的成因分类**，再逐类消除：

| 可能成因 | 本版对策 |
| --- | --- |
| 列被挤出可视区、块跑到相邻列（像素列宽与实际容器不一致） | **结构性重做**：列宽交给布局引擎，块的横向位置用百分比 |
| 历史数据里的脏星期值（`0`/`'7'`/`'周日'`）——渲染按严格相等匹配，会落到错列或消失 | `coerceDayOfWeek()` + 启动时 `normalizeStoredCourses()` 自动规整 |
| 数据本身就没写周日（或写法没被识别） | **课表自检**：把"按星期分布 / 重复项 / 星期字段原值"直接摊给用户，并给出修复建议 |

#### ② 列排版：从"算得准才不出错"到"算错也不出错"（`WeekGrid.tsx` + `layout.ts`）

- 七列 `flex: 1`：由布局引擎均分可用宽度，**永远精确填满容器**，"总宽超出"不可能发生；
- 课程块横向用**百分比**（`lanePercent(lane, lanes)` → leftPct/widthPct）：相对本列，数学上不可能越界；
  并排时的空隙由内层 View 的 `marginRight` 表达，不参与外层几何；
- 竖直方向仍用像素（行高固定，与节次一一对应）；
- 表头与主体用**同一套 flex 分配 + 同样的左右内边距**，逐列对齐由结构保证。

> 由像素改为百分比后，`laneBox`（像素版）被 `lanePercent`（百分比版）取代；
> 单测也从"算出的像素是否合理"改为**结构不变式**：每块都在 `[0,100]%`、相邻首尾相接、合计正好 100%、越界被钳制。

#### ③ 脏星期数据兼容（`select.ts` + `AppStore.tsx`）

- `coerceDayOfWeek(raw)`：数字（`0`→周日，1~7 原样，越界→null）、字符串数字、中文（`周日/星期日/星期天/周六…`）、
  英文（`Sun/Mon/…`）全部识别；
- `coursesForDay` / `coursesInWeek` / `isCourseActive` / `nextCourseToday` **一律先归一化**再比较 ——
  这样即使存储里还是脏值，显示也不会错列；
- `normalizeStoredCourses(courses)` 在 `AppStore` 首次加载时跑一次并写回，返回修正条数
  （经 `AppContext.autoFixedDays` 暴露给自检报告），无法识别的落到周一（不丢课程），**幂等**。

#### ④ 课表自检（`utils/diagnose.ts` + 设置 → 数据管理 → 课表自检）

纯函数 `buildCourseCheckReport(courses, { periods, autoFixedDays })` 产出结构化条目，覆盖：

1. 课程总数；按星期分布（一眼看出周日是否为空）；
2. 星期字段不规范（列出原值）与本次启动自动修正条数；
3. **同一天 + 同一时段 + 同名同地点**的多条（`fingerprint()` 比对）——"一格多天被压平"的痕迹，
   并给出"用原始文件重新导入 / 删掉多余那条"的建议；
4. **周六有课、周日为空**（本次现象）→ 列出周六的课并提示"若周日也上，请重新导入或手动补"；
5. 无周次信息、重复 id、节次超出现有作息表；
6. 一切正常时明确报"未发现异常"。
   `reportToText()` 可一键分享，方便把现场发回排查。

**测试**：`test-crop` 增至 31 项（新增百分比布局不变式、星期兼容、启动规整幂等、自检四类）、
新增 `scripts/verify-v172.mjs`（11 项：四种宽度几何 + 脏数据落列 + 自检结论）。

> ⚠️ **改了 DOM 结构，所有依赖祖先层级的测量都要跟着改**（本轮踩到）：
> 新结构是「日列 > 定位壳(Pressable) > 可见卡片」，比旧结构多一层。
> 旧脚本用 `block.parentElement` 取"所在列"，结果量到的是**半列宽**（22.4），
> v1.7.0 回归的 A3 因此失败 —— 看起来像"重叠课程不再各占半列"，实际是测量层级错了。
> 同理，v1.7.2 的新脚本一开始把**表头文字元素**当列基准（文字只有 22px 宽），
> 导致"块越出本列"全部误报。**列基准要取 flex 容器（表头单元格 / 日列），不是里面的文字。**
