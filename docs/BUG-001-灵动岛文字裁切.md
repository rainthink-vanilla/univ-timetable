## 1. 现象描述

课表页顶部灵动岛收起态中，第二行文字（「今天没有课，好好休息 🎉」／课程名）**贴着胶囊下边缘，缺少下内边距**；文字量多时会被容器裁切（`overflow: hidden`）。

同一现象在灵动岛展开态**不可见**——因为展开态把高度撑到了内容实测高度。

### 触发条件
- 设备：Android（中文环境）
- 状态：灵动岛为**收起态**，且内容为**两行**（第一行「第 N 周 · 周X M/D」，第二行课程名或空态提示）
- 用户报告的实例：第 2 周、当天无课 → 第二行是空态文案

2. **第一行与第二行的行距不均匀**——第二行明显更贴底。

## 4. 根因分析

### 4.1 直接原因：收起态高度被写死为 46，容纳不下两行内容

`src/components/DynamicIsland.tsx:19-20`

```tsx
const [collapsedH, setCollapsedH] = useState(46);
const [expandedH, setExpandedH] = useState(46);
```

第 33 行把它接进动画，第 37 行作为容器高度：

```tsx
const height = anim.interpolate({ inputRange: [0, 1], outputRange: [collapsedH, expandedH] });
// 收起态 height = 46
<Animated.View style={[styles.island, { height, borderRadius: br }]}>
```

容器还有 `overflow: 'hidden'`（第 99 行），**内容一旦超过 46 就被裁掉**。

### 4.2 关键：Android 中文字体的 `includeFontPadding`

`src/components/DynamicIsland.tsx:120, 123`

```tsx
mainText: { color: '#fff', fontSize: font.small, fontWeight: '700' },   // 13pt
nextText: { color: '#CBD5E1', fontSize: font.tiny, flexShrink: 1 },     // 11pt
```

两处文本都**没有设置 `lineHeight`**，也没有关闭 `includeFontPadding`。
React Native 在 Android 上默认 `includeFontPadding: true`，中文字形的实际行盒比
`fontSize` 高出约 4–6pt。于是收起态实际需要的高度约为：

```
paddingVertical 12 × 2                     = 24
第一行（13pt + fontPadding）≈ 22
第二行（11pt + fontPadding）≈ 19
───────────────────────────────────────────
合计                                       ≈ 65  >  46      ← 溢出约 19
```

**容器 46 < 内容约 65**，所以第二行被裁。这解释了为什么「展开态正常、收起态异常」：
展开态的 `height` 来自实测值，能撑开；收起态默认就是 46。

### 4.3 放大因素：`collapsedH / expandedH` 互相覆盖

```tsx
// 第 42-44 行（收起态测量）
onLayout={(e) => { if (!expanded) setCollapsedH(e.nativeEvent.layout.height); }}
// 第 65 行（展开态测量）
onLayout={(e) => setExpandedH(e.nativeEvent.layout.height)}
```

两个状态**共用一个初始值 46**，且由两个 `onLayout` 分别写入：

- 首帧两个测量回调都还没触发 → 收起态用 `46`，即**必然先裁一次**；
- 收起态的 `onLayout` 把 `collapsedH` 修正为实测值（≈65）后，容器变高——但它同时挂在
  `anim.interpolate` 的 `outputRange` 上，会产生一次可见的高度跳变；
- 展开态的 `onLayout` 在**未展开时也会触发**（该 `Animated.View` 始终渲染，只是 `opacity: 0`），
  把 `expandedH` 写成内容高度；而空态（`next == null`）展开内容实测同样约 46，
  于是 `expandedH` 被压回 46 → **展开动画的高度插值失效**（这属于连带缺陷，见 BUG-002）。

### 4.4 完整代码位置

| 文件 | 行 | 问题 |
| --- | --- | --- |
| `src/components/DynamicIsland.tsx` | 19–20 | 高度写死 46，两状态共用初值 |
| `src/components/DynamicIsland.tsx` | 33, 37 | 写死高度直接用于容器 `height` |
| `src/components/DynamicIsland.tsx` | 42–44, 65 | 两个 `onLayout` 互相覆盖 |
| `src/components/DynamicIsland.tsx` | 99 | `overflow: 'hidden'` 把溢出变成裁切 |
| `src/components/DynamicIsland.tsx` | 107–113 | `paddingVertical: 12` 未计入高度预算 |
| `src/components/DynamicIsland.tsx` | 120, 123 | 无 `lineHeight`、无 `includeFontPadding: false` |

| 维度 | 评估 |
| --- | --- |
| 功能 | 无影响：课程数据、导入、视图切换均正常 |

## 6. 修复建议

三处一起改才有效（单独调高 46 只是把问题推后，换个字号/机型又会出现）：

1. **不写死高度**：收起态与展开态各自 `onLayout` 实测，用两个独立 state，再用
   `Animated.interpolate` 在「实测收起高 → 实测展开高」之间插值；
2. **首帧不约束高度**：两个高度都还没测出时不要给 `height`，让内容自然撑开，
   避免首帧先裁一次再跳变；
3. **文本显式声明行高**：加 `lineHeight`（如 13pt → 18、11pt → 16）与
   `includeFontPadding: false`，并加 `maxFontSizeMultiplier={1.3}` 防止大字号撑爆。

> 与此前的一版实现不同，本次修复**不含**「按周次列表」功能——该功能仍在
> `git stash@{0}`（消息：`v1.2.0-WIP-灵动岛修复+按周次列表`），需要时再单独取回。

## 8. 修复实现（2026-09-10）

### 8.1 改动文件
`src/components/DynamicIsland.tsx`（仅此一个文件）

### 8.2 针对 BUG-001 的三处修改

| # | 改动 | 对应根因 |
| --- | --- | --- |
| 1 | `collapsedH`/`expandedPanelH` 初值由 `46` 改为 `0`，高度全部由 `onLayout` 实测写入 | 4.1 写死高度 |
| 2 | 两个高度都未测出前**不设** `height`，让内容自然撑开；测出后才交给 `Animated.interpolate` | 4.3 首帧先裁一次再跳变 |
| 3 | 所有文本加显式 `lineHeight`（13→18、11→16、15→21）与 `includeFontPadding: false`，并加 `maxFontSizeMultiplier={1.3}` | 4.2 中文字体额外内边距 |

关键代码：

```tsx
const ready = collapsedH > 0;
const openH = expandedPanelH > 0 ? collapsedH + expandedPanelH : collapsedH;
const height = ready
  ? anim.interpolate({ inputRange: [0, 1], outputRange: [collapsedH, Math.max(openH, collapsedH)] })
  : undefined;   // 未测出 → 不约束高度
```

另将收起态层从「随内容参与布局 + 居中」改为**绝对定位锚在左上角**
（`styles.collapsedLayer`）：外层高度由动画接管后，`alignItems: 'center'` 会依赖父容器高度，
在父高未定时造成裁切/偏移。

### 8.3 针对 BUG-002 的修改
展开面板改为**仅在展开时渲染**，并单独测量其自身高度：

```tsx
{expanded ? (
  <Animated.View style={[styles.expanded, { opacity: anim }]}>
    <View onLayout={(e) => setExpandedPanelH(Math.ceil(e.nativeEvent.layout.height))}>
      …展开内容…
    </View>
  </Animated.View>
) : null}
```

这样 `expandedPanelH` 量到的是展开面板自身高度（不再被收起态干扰），
终值取 `collapsedH + expandedPanelH`，两个状态不再互相覆盖。

### 8.4 验证结果

Web 构建 + 无头 Chrome，用 **CDP 真实鼠标事件**触发展开（合成的 `dispatchEvent`
无法驱动 RN Web 的 Responder 系统），测量结果：

| 场景 | 岛高 | 内容高 | 上/下留白 | 裁切 | 文本行数 |
| --- | --- | --- | --- | --- | --- |
| 收起态·有课 | 42 | 18 | 12 / 12 | 否 | 2 |
| 展开态·有课 | **112** | 73 | 12 / 27 | 否 | 5 |
| 收起态·无课 | 42 | 18 | 12 / 12 | 否 | 1 |

断言 6/6 通过，其中关键两条：

- BUG-001：三种场景均 `clipped = false`，且下留白 ≥ 6pt；
- BUG-002：展开高度 112 > 收起高度 42（差值 70），**插值未退化**。

> **Web 与 Android 的差异说明**：Web 无 `includeFontPadding`，故收起态内容高仅 18pt；
> Android 上同一内容会更高，而修复后的高度是**实测驱动**的，容器会随之变高——
> 这正是选用实测而非写死数值的原因。因此 Web 上的 6/6 验证的是**修复机制成立**；
> Android 的最终像素值仍需真机复核（见第 7 节未勾选项）。

# 附：BUG-002（顺带发现，独立缺陷）

| 项目 | 内容 |
| --- | --- |
| 严重级别 | P3 / 低 |
| 位置 | `src/components/DynamicIsland.tsx:65`（展开高度测量） |
| 状态 | ✅ **已修复**（见 8.3） |

**描述**：展开态的 `onLayout` 在**组件始终渲染**（`opacity: 0` 覆盖显示）的情况下都会触发，
因此 `expandedH` 在未展开时就被写成展开内容的高度；当 `next == null`（空态）时展开内容仅一行，
实测高度 ≈ 46，与收起态相同 → **展开/收起的高度插值退化为常量**，动画失去高度变化效果。

**修复**：展开面板改为展开时才渲染，并单独测量（8.3）。

# 附：观察记录（未定性，供排查参考）

截图中存在一处**日期不一致**，本报告未能确证其成因，仅作记录：

| 位置 | 显示 |
| --- | --- |
| 灵动岛 | 第2周 · **周四 9/10** |
| 日期栏 | **9月7日 周一**（且未显示「今天」徽标） |

同一时刻两处日期不一致。代码上二者来源不同：

- 灵动岛：`TimetableScreen.tsx` 用 `dayOfWeekNumber(now)` + `shortDate(now)`，**直接取自当前时间**；
- 日期栏：`DayView.tsx:37` 用 `dateForWeekday(semesterStart, week, index + 1)`，日期由
  `semesterStart + week + index` **推算**，而 `index` 是组件内部 state（第 29 行初始化自
  `todayIndex`，第 32–35 行的同步 `useEffect` 依赖数组只有 `[width]`）。

因此**若 `index` 与实际当天星期不一致，日期栏就会显示错误日期**，且不会自动纠正。
已验证 `useNow.ts`（第 5–9 行）的定时刷新逻辑本身正确（`useState(new Date())` 惰性初始化 +
`setInterval` 30s），**不是**时钟不刷新导致。

**建议后续单独立项**：让 `DayView` 的 `index` 在 `todayIndex` 变化时重新同步，
并把 `isToday` 判定与滚动位置解耦。此项与 BUG-001 无因果关系，不应合并修复。
