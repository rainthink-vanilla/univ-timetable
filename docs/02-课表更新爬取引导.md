# 02 · 课表更新爬取引导（可填爬取范围）

> 已经完成过首次导入、只想更新课表时用这个文件。
> 不需要重填账号密码的完整信息——只要告诉 agent「从哪来、抓多宽」。
>
> 契约版本：`univ-timetable/v1`（与 `01-用户信息表与爬取引导.md` 完全一致）

---

## 0. 怎么用

1. 填下面第 1 节（**只有 4 行**）。
2. 对 agent 说：**「按 `02-课表更新爬取引导.md` 执行更新。」**
3. agent 产出 `课表更新-<学号>-<日期>.md`。
4. 手机 App →「导入 → 文件导入」→ 选文件 → 导入方式选 **「更新合并」**。
5. 看到提醒后**去改密码**。

> 首次导入请用 `01-用户信息表与爬取引导.md`。

## 2. 爬取范围对照表（选一个填进上表）

| 范围值 | 抓取内容 | 产出课程量 | 适用场景 |
| --- | --- | --- | --- |
| `day` | 今天会上课的课程 | 最少 | 当天临时调课、停课确认 |
| `week` | 当前教学周会上课的课程 | 少 | 每周日更新下周课表 |
| `month` | 当前月覆盖到的周次（如第 9-12 周） | 中 | 每月一次例行更新 |
| `all` | 整个学期全部课程 | 全部 | 系统大改、补全遗漏 |
| `term` | 指定学期全部课程 | 全部 | 跨学期切换 |
| `custom` | 第 1 节指定的周次 | 自定义 | 补抓某几周 |

**范围怎么影响 App 里的数据？**

| App 导入方式 | 行为 |
| --- | --- |
| **更新合并**（推荐） | 文件里出现过的课程按「课程名 + 星期 + 开始节次」匹配，**原地更新**；文件里没有的课程**保持不动** |
| 整体替换 | 清空现有课表，完全使用文件内容（**窄范围更新时不要选这个**，会只剩几门课） |
| 追加 | 直接往后加，可能产生重复 |

> 所以：**窄范围更新（`day`/`week`/`month`/`custom`）一定要选「更新合并」。**

### 2.1 更新时要不要带「节次时间表」？

**默认不要带。** 但要知道它的影响，因为**只要文件里给了节次时间，导入时就会覆盖 App 里的设置**。

| 情况 | 建议 |
| --- | --- |
| 学校作息没变（绝大多数情况） | **不写**节次时间表 → App 保留你现有/手动调好的时间 |
| 换学期后学校改了作息 | 带上，让 App 自动更新 |
| 你手动微调过节次时间 | **不写**，否则会被文件覆盖回去 |
| 拿不准 | 不写。真要改，之后在 App「设置 → 学期 → 节次时间表」里改更省事 |

> 如果你在 App 里手动改过上课时间，而更新文件又带了节次时间表，导入时会被文件的值覆盖。
> 01 首次导入时带上是有意义的（省得手动填），**日常更新则没必要重复带**。

带的时候按下面两段写（表格给人看，JSON 给 App 读，两者必须一致）：

| 节次 | 时间 |
| --- | --- |
| 第1节 | 08:30 - 09:15 |
| 第2节 | 09:25 - 10:10 |

```json
"periods": [
  { "index": 1, "start": "08:30", "end": "09:15" },
  { "index": 2, "start": "09:25", "end": "10:10" }
]
```

> 也可以只给推算参数，App 会自动展开：
> `"periodTimes": { "start": "08:30", "duration": 45, "break": 10, "count": 12 }`

## 3. agent 执行步骤

1. 打开「教务系统登录地址」，用第 1 节账号密码登录（验证码处理同 01 文件 3.1 节）。
2. 进入课表页；**先切到「全学期视图」**，再按范围过滤，否则会漏课。
3. 按范围取数：
   - `day`：取今天（星期几 = 今天）当天会上的课，周次必须包含当前教学周；
   - `week`：取当前教学周会上的课。**当前教学周 = floor((本周周一 − 学期开始那周的周一) / 7天) + 1**
     （即按「周一对齐」计算，不要用自然日差）；
   - `month`：取当前月日期覆盖到的周次区间内会上的课；
   - `all`/`term`：取全部周次全部课程；
   - `custom`：取第 1 节「自定义周次」内的课程。
4. 采集字段与约束**完全沿用** `01-用户信息表与爬取引导.md` 第 3.4 与第 4 节。
5. **节次时间表：默认不带**（见第 2.1 节）。仅当第 1 节明确要求「学校作息有变」时才带上，
   且必须同时更新表格与 JSON 两处。
6. 在「课表元信息」表里把 `覆盖周次` 写成实际抓取的周次（如 `9-12`），`爬取范围` 写成范围值，`爬取时间` 写当前时间。
7. 自查：课程数量 = 课表页在范围内显示的课程数；每门课都有 星期 + 节次 + 周次。

### 3.1 窄范围更新的特别注意

- **不要**因为范围窄就省略周次字段——即使只抓第 9 周，也要写 `"weeks": [9]`。
- 只抓到了「周一 1-2 节」的一门课，就不要顺手把该课程其他时间的安排也写进去（那属于超范围）。
- 如果发现某门课**被取消了**（课表里没了），范围更新**不会**自动删除它——请在 App 里手动删除，或改用 `all` + 「整体替换」。

## 6. 什么时候该用 `all` + 整体替换？

- 换学期（学期开始日期、总周数都变了）；
- 教务系统改版 / 补考重修导致课表结构大改；
- 发现课表里有大量已取消的课程（合并方式不会删除它们）。

此时范围填 `all`，App 导入方式选「整体替换」，一次性重建。
