# 01 · 用户信息表与 agent 爬取引导

> **这个文件是给「你 + 你的 agent」共用的。**
> 你负责填第 1 节，agent 负责读第 1 节、按第 3 节执行、按第 4 节产出课表文件。
>
> 契约版本：`univ-timetable/v1`　（App 与本文件使用同一套格式，改动需同步）

---

## 0. 怎么用（30 秒版）

1. 把本文件复制一份到你能让 agent 读到的地方（或直接整份贴进对话）。
2. 填写下面第 1 节的表格（教务系统地址、账号、密码、爬取范围）。
3. 对 agent 说：**「按 `01-用户信息表与爬取引导.md` 第 3 节执行，产出第 4 节格式的文件。」**
4. agent 产出 `课表-<学校>-<学号>.md` 后，用手机 App「导入 → 文件导入」选中它。
5. **看到 App 的提醒后，立刻去教务系统改密码。**

> ⚠️ 本文件含有账号密码。**不要**把它提交到 git、不要发到群里、用完建议删除或清空第 1 节的密码行。

### 1.1 为什么要填「第 1 节上课时间」

**各校作息差异很大**，这是最容易被忽略、但直接影响「下一节课是几点」的一块：

| 学校 | 第 1 节 | 每节 | 课间 |
| --- | --- | --- | --- |
| A 大学 | **08:00** | 45 | 10 |
| B 学院 | **08:30** | 40 | 10 |
| C 大学 | **08:15** | 50 | 5 |

App 用这张表来算：**「下一节课 14:00 - 15:40」这类提示**、课程卡片上的上下课时间、
以及「正在上课」的高亮判断。填错了不会崩溃，但时间提示会整体偏移。

**你只需要填「第 1 节上课时间」**，其余留空由 agent 从教务系统「作息时间表 / 上课时间表」
页面取；学校页面没有的话，按下面的常见默认值猜也可以：

- 每节课时长：45 分钟（多数高校）
- 课间休息：10 分钟
- 每天节数：12 节

> 也可以**完全不填**，agent 会按 45/10 推算，之后在 App 的
> 「设置 → 学期 → 节次时间表」里再手动微调。

## 2. 爬取目标（agent 必读）

> **唯一目标：拿到这名学生本人的课表。** 不得抓取其他学生、教师、成绩、财务、学籍等任何无关数据。

- **只读**：只做登录 + 读取课表页面，**禁止**任何写操作（选课、退课、提交表单、改密码）。
- **只要课表**：不导出成绩单、不导出个人信息页、不下载附件。
- **数据完整**：把课表页上的每一门课、每一节次都取到，**不许省略、不许合并、不许只取第一页**。分页/多学期/多校区的都要翻完。
- **字段齐全**：至少包含 课程名称、教师、地点、星期、节次、周次；能拿到的 课程代码、学分、课程性质、教学班、备注 一并写入扩展字段。
- **不做推断**：页面没有的信息留空，不要自己编教师名或教室号。

## 3. 执行引导（agent 按顺序做）

### 3.1 登录

1. 打开第 1 节的「教务系统登录地址」。
2. 用第 1 节的账号密码登录。
3. 若出现验证码：
   - 图形验证码 → 截图给用户，让用户口述/输入；
   - 短信验证码 → 提示用户输入；
   - **不要**尝试绕过验证码、不要调用打码接口。
4. 登录成功后先确认页面出现学生姓名，确认是**本人**账号。

### 3.2 定位课表页

1. 优先打开第 1 节的「课表页地址」。
2. 若地址为空或打不开：在系统里依次找
   `信息查询 / 我的课表 / 学生课表查询 / 课表查询 / 培养方案 → 课程表` 等入口。
3. 常见教务系统的课表页特征：

| 教务系统 | 常见课表入口 / 特征 |
| --- | --- |
| 正方教务（jwglxt） | `kbList` 接口或 `xskbcx` 页面，表格含「课程名称/教师/周次/节次/教室」 |
| URP 综合教务 | 「综合查询 → 学生课表查询」，多为打印视图 `printTimetable` |
| 强智教务（qzkj） | 「信息查询 → 学生个人课表」，页面含 `kbgrid` 表格 |
| 教务网络管理系统（jwweb） | 「学生课表查询」或 `xkbcx`，含校区/教学楼筛选 |
| 超星 / 今日校园 | 「我的课表」或导出 `.ics` / `.xls` |

4. 如果课表按周显示，**先切换到「全学期 / 全部周次」视图**再抓，避免只拿到当前周。
5. 如果有多个学期标签页，**只抓第 1 节填写的那个学期**。
6. **顺手找一下「作息时间表」**：多数教务系统有「上课时间表 / 作息时间 / 节次时间」页面
   （常和课表放在一起，或叫「校历」「上课时间」）。找到就把各节次的起止时间抄下来，
   写进产出文件的「节次时间表」——这块决定 App 里「下一节课 14:00」显示得对不对。
   找不到就按第 1 节填的「第 1 节上课时间 + 45 分钟/节 + 10 分钟课间」推算。

### 3.3 选择爬取范围（第 1 节已填，这里是对照表）

| 范围值 | 含义 | 抓什么 | 适用场景 |
| --- | --- | --- | --- |
| `all` | 整个学期 | 全部周次、全部课程 | **首次导入，推荐** |
| `term` | 指定学期 | 该学期全部课程 | 系统里存了多个学期时 |
| `week` | 当周 | 仅当前教学周会上课的课程 | 只想看这周有没有调课 |
| `day` | 当日 | 仅今天会上课的课程 | 临时确认今天课表 |
| `month` | 当月 | 当前月覆盖到的周次 | 月度更新 |
| `custom` | 自定义周次 | 第 1 节「自定义周次」指定的周次 | 补抓某几周 |

> **重要**：范围越窄，产出的文件课程越少。导入 App 时选「更新合并」只会覆盖文件里出现过的课程，不会删掉其他课程——所以窄范围更新是安全的。

### 3.4 采集字段

**必需字段（缺一项就算不合格）**

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 课程名称 | 完整课程名，保留括号 | 高等数学A（下） |
| 教师 | 多位教师用 `/` 分隔 | 张三/李四 |
| 地点 | 教学楼+教室，含校区 | 东区教一101 |
| 星期 | 周一到周日 | 周一 |
| 节次 | 起止节次 | 第1-2节 |
| 周次 | 上课周次，支持单双周 | 1-16 / 1-16周(单) / 1-8,10-12 |

**扩展字段（能拿到就写进 JSON 的 `extra`）**

课程代码、学分、课程性质（必修/选修）、教学班号、校区、备注。

**另需单独采集：节次时间表（各校作息不同）**

| 字段 | 说明 | 示例 |
| --- | --- | --- |
| 节次 | 第几节 | 第1节 |
| 开始时间 | 24 小时制 | 08:00 / 08:30 |
| 结束时间 | 24 小时制 | 08:45 / 09:15 |

采集优先级：

1. 教务系统的「上课时间表 / 作息时间」页面（**最准，优先**）；
2. 课表页面上每节课旁边标的时间；
3. 第 1 节用户填的「第 1 节上课时间」+ 45 分钟/节 + 10 分钟课间**推算**。

### 3.5 抓取手法（按系统实际情况选一种或组合）

1. **页面文本**：直接复制课表表格文本 → 自己解析成结构化数据。
2. **接口**：打开开发者工具，找课表接口（如 `POST /jwglxt/kbcx/xskbcx_cxXsgrkb.html`），带 cookie 请求一次拿 JSON。**只请求课表接口，不要遍历其他接口。**
3. **导出文件**：系统若支持导出 `.xls/.csv/.ics`，下载后解析。
4. **截图识别**：实在取不到结构化数据时，截图 + 视觉识别，但要**人工核对**每一门课。

### 3.6 自查（产出前必须过一遍）

- [ ] 课程数量与课表页显示一致？
- [ ] 每门课都有 星期 + 节次 + 周次？
- [ ] 单双周、分段周次（`1-8,10-12`）没有丢？
- [ ] 同一门课不同时间的多个安排（如周一1-2节 + 周三3-4节）拆成了多条？
- [ ] 连堂（3-4 节）没有漏掉后半节？
- [ ] 多页 / 多校区的课程都翻完了？
- [ ] 没有混入其他学生的课程？
- [ ] **节次时间表已填**（至少给了「第 1 节上课时间」）？

### 4.1 字段规范

| 字段 | 类型 | 必填 | 规范 |
| --- | --- | --- | --- |
| `name` | string | ✅ | 课程名称 |
| `teacher` | string | ✅ | 无则填 `""` |
| `location` | string | ✅ | 无则填 `""` |
| `dayOfWeek` | number | ✅ | `1`=周一 … `7`=周日 |
| `startPeriod` | number | ✅ | 开始节次，从 1 开始 |
| `endPeriod` | number | ✅ | 结束节次，连堂如 1-2 填 2 |
| `weeks` | number[] | ✅ | 升序去重的周次数组，如 `[1,2,3]` |
| `note` | string | ❌ | 备注 |

### 4.2 硬性约束

- 星期只能用 `1-7` 数字；节次只能用 `1-20` 数字；周次必须是数字数组（**不要**写成 `"1-16周(单)"` 字符串）。
- 一门课在同一星期同一节次只出现一次；不同时间的不同安排必须拆成多条记录。
- 表格里**不要**出现 `|` 字符（会破坏表格）；用 `/` 代替。
- JSON 必须是合法 JSON（可被 `JSON.parse` 直接解析），代码块语言标记写 `json`。
- 表格与 JSON 内容必须一致；App 优先读 JSON，表格用于人工核对。

## 6. 常见问题

**Q：登录有验证码怎么办？**
A：图形验证码截图给用户识别；短信验证码让用户输入。不要用打码平台。

**Q：课表是图片或 PDF 怎么办？**
A：截图/转图片后用视觉识别，然后**逐条人工核对**，再产出契约文件。

**Q：一个课程在课表里跨多个格子（连堂）怎么记？**
A：合并为一条，`startPeriod`/`endPeriod` 分别填首尾节次。

**Q：单双周怎么表示？**
A：展开成数组，如 `1-16周(单)` → `[1,3,5,7,9,11,13,15]`。

**Q：老师只给了一周的课表（临时调课）？**
A：范围选 `week` 或 `day`，并在「覆盖周次」写清是第几周。导入 App 时用「更新合并」，只会覆盖对应课程。

**Q：想更新课表，不想重新填信息？**
A：用 `02-课表更新爬取引导.md`，它是本文件的精简版，只需要填「爬取范围」。
